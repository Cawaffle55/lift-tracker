# Lift Tracker

An installable, offline-first workout set/rep tracker (PWA) inspired by Hevy. Pure static files — no build step, no server, no account. All data stays on the phone (IndexedDB).

## Run / host
Any static host serving this folder as the site root (all paths are relative, so a sub-path like `https://user.github.io/lift-tracker/` works):
```
python3 -m http.server 8080    # then open http://localhost:8080
```
A service worker needs **HTTPS** (or localhost) — GitHub Pages, Netlify, Cloudflare Pages all qualify.

**Install on iPhone:** open the URL in Safari → Share → *Add to Home Screen*. **Android:** Chrome menu → *Install app* (or Settings tab → *Add to home screen*).

**Updating:** after changing files, bump `VERSION` in `sw.js`. The app serves from cache first and refreshes in the background, so changes show up on the next launch.

## Built-in programs
On first launch the app seeds three programs: **Starter PPL** (a suggested 6-day push/pull/legs starter routine to edit to fit you; active by default; 1 repeating week, 6 days, weekly order Legs 1 → Push 1 → Pull 1 → Legs 2 → Push 2 → Pull 2 → Rest, supersets, %1RM loads) **Example PPL (sample)** and **Bodyweight Full Body (sample)** (Day A / B / C with rest days between, no equipment, 1:30 rest, timed planks/holds; not active by default). Deleting them is permanent until *Programs → Restore built-in programs*.

Built-in definitions are versioned (`BUILTIN_VERSION` in `js/app.js`). When it is bumped, existing installs replace the bundled programs' definitions on next launch (programs the user deleted stay deleted, programs the user edited in the app are not overwritten, and newly added built-ins appear); workout history, settings and other programs are not touched. v1.2 also migrates the old 120 s default rest to 90 s.

## Rest timer
Default rest is **1:30 (90 s)**. Settings → *Default rest time* (±15 s steps) and *Use default rest for all exercises* (on by default; turn off to use each exercise's program rest where it has one, falling back to the default). Warm-up sets use a separate *Warm-up set rest* (default 1:00, never longer than the working rest). Tap the default rest or the running timer to **type** a time (`90`, `1:30`, `2 min`). Per exercise: ⋯ → *Progression & rest* (or tap the rest pill) sets its own working and warm-up rest. Drop sets skip the timer. While resting, tap −15 / +15 / Skip on the timer bar. The built-in Starter PPL uses 1:30 for every exercise; regenerate with `../lift-tracker-data/build.py` then `convert.py`, both of which keep 90 s.

## Sounds & haptics
All sounds are synthesized with Web Audio (no audio files): a warm pop-ding per completed set (E6 + a perfect fifth, soft attack, short reverb shimmer), a rising arpeggio when every set of an exercise is done, a brass fanfare on finishing a workout, and a bright rising A–C♯–E alert played twice when rest ends. **New PRs are celebrated live**: when a completed working set's weight is strictly heavier than the heaviest weight you've ever logged for that lift in any saved workout (units converted) and than this session's earlier sets, you get a synthesized horn fanfare (rising G–C–E–G into a held C-major chord), a celebratory vibration, confetti and a “New PR!” badge. The first time you log a lift with weight counts too. Matching a past weight, or more reps at the same or lower weight, never triggers; warm-ups never count. The end-of-workout PR list uses the same rule. Haptics use `navigator.vibrate` where supported (Android; iOS Safari has no vibration API, so it's skipped silently): a 20 ms tick per set, a long double buzz (200-100-200 ms) when rest is over, and a da-da-da-DAAA rumble on a PR. Settings → *Sounds & haptics*: sounds on/off, volume, haptics, and test buttons. Audio is unlocked on the first tap (iOS requires a user gesture).
**iPhone note:** the ring/silent switch mutes web audio — if you hear nothing, flip the switch off silent. Sounds also can't play while the app is in the background, so a rest that ends while the phone is locked alerts when you return.

## iPhone / Safari (v1.6.2)
Tested under WebKit with an iPhone 14 profile (all suites run with `LT_BROWSER=webkit node tests/<suite>.js`).
- Add it to the Home Screen (Share → Add to Home Screen) for full-screen and to keep Safari from clearing its storage after about 7 days of no use. Export a backup now and then.
- Sounds start after your first tap, and the ring/silent switch mutes them. They mix with your music instead of pausing it.
- iPhone Safari has no vibration API, so haptics are skipped.
- iOS pauses the app when the phone is locked or you switch apps. The rest timer keeps the correct time and catches up when you come back, but the "rest over" sound can't play while it's in the background.

## Exercise library
**978 exercises** in `data/exercises.json` (≈435 KB, ≈70 KB gzipped, precached for offline use): equipment, primary/secondary muscles, category (push/pull/legs/core/full body/conditioning/stretch), a 1–2 sentence description, and timed tracking for holds. 301 are bodyweight.
- **Source:** 876 entries come from [free-exercise-db](https://github.com/yuhonas/free-exercise-db) by yuhonas, pinned to commit `f00c92c7dcf1216a928a52c3706c7ce8e2f71ed5`. Its license is the **Unlicense** (public domain dedication, see its `LICENSE.md`; the project describes itself as an "Open Public Domain Exercise Dataset", and its data and images originally came from wrkout/exercises.json, also Unlicense). Descriptions are condensed from its instructions; about 25 common lifts have hand-written ones.
- 102 extra entries (ids `lt-…`) were written for Lift Tracker: push-up, pull-up and dip variants, calisthenics skills (handstand, levers, L-sit, planche), lunges/split squats, core holds, conditioning moves, and gym staples that were missing (Bayesian curl, pendulum squat, etc.). They have no photos.
- Rebuild: `python3 tools/build_library.py [path/to/exercises.json]` (it downloads the pinned dataset when no path is given).
- **Search** (Exercises tab): instant and case-insensitive as you type. Multiple words are ANDed. Equipment words (`dumbbell`, `db`, `barbell`, `cable`, `bodyweight`/`no equipment`/`calisthenics`, `kettlebell`, `smith`…) become strict filters, muscle words and synonyms (`chest`/`pecs`, `back`, `legs`, `abs`/`core`, `quads`…) match primary/secondary muscles, and everything else matches names and aliases (`pull up` = `pullup` = `Pullups`). There are also equipment and muscle filter chips. Results are ranked by muscle relevance, then popularity. Your logged exercises are listed first.
- **Detail**: description, muscles, equipment, your PRs/history, **Add to workout or program…**, and **▶ Watch on YouTube**, which opens a YouTube *search* for "<name> proper form" (no embeds).
- **Form photos**: free-exercise-db's public-domain start/end photos alternate every second (tap to pause). They load lazily from jsDelivr (`cdn.jsdelivr.net/gh/yuhonas/free-exercise-db@<commit>/exercises/<id>/0.jpg`) only when you open a detail or ⓘ card. The service worker caches viewed photos (up to 600) so they work offline afterwards. Exercises without a free photo show text only, and a photo that fails to load is removed quietly.
- **Custom exercises**: when a search finds nothing, *Create "…"* adds your own (equipment, muscle, reps/time). They are stored on the device and included in backups.
- **Credits** are shown on every detail card and in Settings → About & credits.

## Creating workouts
- **Programs → ＋ Create a program from scratch**: give it a name and a comma-separated list of days, which opens the day editor.
- **Day editor** (also *Programs → program → Edit days*): rename the day, add notes, **＋ Add exercise** (opens the library in picker mode; tap + on as many as you like, then Done), and ↑ ↓ to reorder, ✎ to edit (warm-ups, sets, reps, RPE, rest — default 1:30, notes, reps vs. seconds, bodyweight) or ✕ to remove. Then **Start this day**.
- **From any exercise detail**: *Add to workout or program…* → the current workout, or any program → day.
- **Mid-workout**: *＋ Add exercise* at the bottom of a workout opens the library picker and adds it to the session.
- Workout cards get an **ⓘ** button with the description and photos whenever the exercise matches a library entry. All built-in program exercises match.

## Bodyweight & timed sets
Bodyweight exercises (from the library or `"bodyweight": true`) treat weight as optional: an empty weight logs as **BW**, and added weight (e.g. a vest or belt) logs as **BW+25**. The weight pad has *Bodyweight only (BW)*. Timed holds (`"tracking": "time"`) show a **Secs** column with ±5 s steps, log seconds ("35 s"), get a *Longest hold* PR, and are left out of volume.

## Using it
- **Workout tab**: shows the active program and the *next day in sequence* (after your last finished day of that program; wraps around). Pick any week/day to preview and start, or start an empty workout.
- **Logging**: each exercise shows targets (warm-up sets, sets × reps, RPE/RIR, technique, rest), notes, substitutions and *last time* you did it. Each set row has *Prev* (tap to copy), weight (tap → quick pad with ± steps and "use for remaining sets"), reps with −/+ and a ✓. Checking a set fills empty fields from the grey placeholders and auto-starts the rest timer (1:30 default; ±15 s / skip; sound + vibrate at 0). Per-exercise and per-workout notes. ⋯ menu: swap to a substitution, move, remove, view history. The in-progress workout is saved on every change and survives closing the app.
- **Finish** saves completed sets only (unchecked ones are discarded) and flags PRs (heaviest weight, best estimated 1RM, Epley).
- **History**: past workouts with duration/sets/volume; tap for details or delete. **Exercises**: per-exercise PRs, e1RM trend and all sessions.
- **Programs**: import JSON/CSV files, paste text, load the sample, set active, export, edit JSON, delete. Multiple programs supported.
- **Settings**: lb/kg (default lb), rest-timer options, **Export backup / Import backup (merge or replace)**, erase data.

## v1.4 training features
Everything runs offline on the phone; nothing is uploaded. None of these add a tap to the normal "check the set" flow.
- **Progressive-overload suggestions**: from your last sessions. Rep ranges (`8-12`) use *double progression* (add reps until every set hits the top, then add weight and drop to the bottom of the range). Fixed reps (`5`) use *linear* progression (add weight after a session where every set hit the target; repeat on a miss; after 3 misses in a row, deload 10%). If every set was RPE ≤ 7, the jump doubles. Default steps: 5 lb, 2.5 kg (2 kg for dumbbells). Bodyweight → +1 rep, timed → +5 s. The suggestion is pre-filled in **blue dashed** fields with a "Suggested: …" line, so one ✓ logs it; typing anything overrides it. Settings → *Progression* turns pre-fill off (then a **Use** button appears) or suggestions off. Per exercise (⋯ → *Progression & rest*): mode, weight step, deload %.
- **Plate calculator**: in the weight pad for barbell lifts (a button for the others) and in Settings → *Plates & bar*, with your bar weight and plate counts for lb and kg. It shows the plates per side with a drawing, or the closest loadable weights when a weight can't be loaded exactly.
- **Warm-up calculator**: ⋯ → *Add warm-up sets* builds warm-ups from the working weight with your ramp (default `bar×10, 40%×5, 60%×5, 80%×3`, editable in Settings), rounded to weights your plates can load.
- **Set tags**: tap the set number to cycle normal → **W** warm-up → **F** failure → **D** drop set. Drop sets pre-fill ~80% of the previous set, skip the rest before them, and are left out of progression.
- **RPE / RIR** (optional, Settings → *Effort*): adds a column; tap to pick. Shown as `@8` or `RIR 2` in history.
- **Pinned notes**: ⋯ → *Pin a note* (seat height, grip, cues) shows on that exercise in every session and on its exercise page.
- **Calendar + streak**: History shows a weekly streak (Mon–Sun weeks with at least one workout), this week vs. your weekly goal (Settings), and a month calendar. Tap a day to open it, or an empty past day to log a forgotten workout on that date.
- **Stats** (History → 📊): a front/back **muscle heatmap** and hard sets per muscle (last 7 or 30 days; primary muscle = 1 set, secondary = ½, warm-ups excluded, from the library's muscle data), weekly volume for 12 weeks, and a **monthly report** (workouts, time, sets, volume and PRs vs. the month before, top exercises, muscle split).
- **Progress charts**: each exercise page charts estimated 1RM, top weight, best set, session volume or reps (hold time for timed) over 1M/3M/1Y/All, with the best point in gold.
- **Post-workout summary**: after Finish — streak, each exercise vs. last time and next time's suggestion. **📤 Share image** makes a PNG card and opens the share sheet (Web Share API) or downloads it.
- **Program sharing**: program → 📤 *Share*: as a `.json` file, or as a link whose `#/import/link/…` part holds the whole program (compressed), so opening it on another phone shows the import preview. Nothing is uploaded.
- **Keep screen awake** (Settings → *Workouts*, on by default): Wake Lock while a workout is open (re-acquired when you return to the app; "☀︎ screen on" shows in the header).
- **Mid-workout edits**: ⋯ → *Replace with a library exercise* keeps the sets you already logged. *− Remove set* removes the last unchecked set first. When you finish, *Update “day” in program* (opt-in) saves swaps and set-count changes to the program.
- **CSV history**: Settings → *Import Strong / Hevy CSV…* (also on the empty History page). The format is detected; Strong files don't say lb or kg, so you pick. Warm-up/failure/drop set types, RPE, durations and notes are kept, duplicates are skipped, and exercise names are matched to yours or the library (`Bench Press (Barbell)` → `Barbell Bench Press`). *Export history (CSV)* (Settings or Stats) writes every set with a header row; the importer reads it back.
- **Data**: existing installs migrate automatically. New settings get defaults, history is untouched, and per-exercise preferences are a new `exprefs` store that is included in backups.

## Paste importer
`js/importers.js → parsePastedText(text, {name, repeatWeeks})`. Line by line:
1. **Delimiter detection**: tabs (copied from Excel/Sheets/Numbers), `|` (Markdown tables), commas, else 2+ spaces.
2. **Header rows** (cells containing *exercise* plus *sets* or *reps*) set the column mapping, using the same loose keyword matching as CSV (warm-up, working sets, reps, RPE ×N, RIR, technique, rest, notes, substitution ×N, week, day). A header may repeat before every day.
3. **Section headings**: a single-cell line like `Week 3`, `WEEK 1 – PUSH`, `Push #1`, `Day 2: Pull`, `Upper`, `LEGS:` or any short ALL-CAPS line starts a new week/day. `Rest day` is skipped.
4. **Exercise rows** without a header are classified heuristically: first text cell = name; `3x8-10`/`3 × 8` = sets×reps; integers before the reps = [warm-up] working sets; ranges = reps; `RPE 8`/numbers 5–10 after reps = RPE; `2-3 min`/`90s`/`1:30` = rest; `RIR 1`; technique keywords (drop set, myo, rest-pause, partials, failure…); remaining long text = notes, short text = substitutions. Free-text lines like `Lateral Raise (2 warmups) 3x12-15 RPE 9 90s drop set on last` also work.
5. Unrecognised lines become notes of the previous exercise/day, or are listed as **Ignored lines** in the preview; questionable rows produce **warnings**. Nothing is saved until you tap **Save program**, and you can go back and edit the text.
6. If only one week was found, "repeat for N weeks" copies it.

**Limits**: PDF copy/paste often puts every table cell on its own line or merges columns with single spaces — those layouts can't be reconstructed reliably (rows get skipped or names absorb numbers). Best results: copy from the spreadsheet version, or paste the PDF into a spreadsheet first, then copy the table. Week-specific values only come through if each week's table is pasted under its own `Week N` heading. Images/scanned PDFs need OCR first. Always check the preview; fix leftovers with *Edit JSON*.

## Back navigation (v1.4.1)
Sheets (the ⋯ exercise menu, note editor, plate calculator, info, RPE, settings sheets, …) are history layers: the Android back button/gesture, the iOS edge swipe, browser back, Escape, ✕/Cancel and a tap outside all close just the sheet. Sub-screens opened from a workout (replace/add-exercise picker, exercise history) go back to the same workout at the same scroll position. Only the workout's ‹ button, the Workout tab, Finish, or Discard leave the workout.

## Updates & back stack (v1.4.2)
- New versions install fresh files and take over right away. The app then shows **"Update ready — tap to reload"** and also applies it automatically the next time you reopen the app (never while you're typing or have a sheet open; the workout and scroll position are kept). Settings shows **Version x.y.z** plus a *Check for update* button.
- With a workout in progress, every tab/page you open from it (Settings and its panels, History, Programs, Exercises, Home) goes back to the workout. If the app reopens straight into a workout, Home is put underneath it on your first tap, so Android back never closes the app from a sub-page.

## Onboarding (v1.5.0)
- **Welcome tour** (first launch of a fresh install only): 4 swipeable cards — program / Up next, one-tap set logging with suggestions, the rest timer, history & stats. Skip, Next/Done, dots; back closes it. Existing users are never forced through it.
- **One-time tips** (coach marks) point at the real button: set type, suggested weight, the weight button (plates), ⋯ options, day-editor reorder, Exercises search, History → Stats. One at a time, only right after a tap, only when the button is on screen, never during the first seconds of a rest countdown. They never cover the ✓ column and let taps through, so ✓ still logs in one tap. Dismiss by tapping anywhere, Got it, Escape or back.
- **Settings → Tips & Help**: replay the tour, show tips again, and a how-to guide (`#/help`), which also covers importing, backups, sharing and installing/updating on iPhone and Android.
- Seen-state lives in `settings.onboard`. Tests turn onboarding off with `localStorage['lt-onboard'] = 'off'`.
